# Requirements — Codex引き継ぎ

## 目的と範囲
- **確定**: KiCad 10を使用してPLC制御盤の電気図面を作成・検証する。
- **確定**: 現在の図面は実機製作用ではなく、KiCadの操作検証・サンプル図面が目的。
- **確定**: サンプルの対象機器として三菱電機 MELSEC-Qシリーズの **Q64PN** を指定。Q64PNは電源ユニットでありCPUではない。
- **確定**: KiCadのシンボルライブラリをGitHubで共有したい。
- **確定**: あらかじめ指定したGitHubライブラリを取得・更新できるツールが欲しい。
- **確定**: このライブラリ同期ツールはKiCad内ボタンではなく、**独立したGUIツール**を希望（後の発言による変更）。
- **確定**: KiCad 10で、**電線1本ごと**の線番管理を実現したい（電位・ネット単位ではない）。
- **確定**: 線番管理の具体的設計と自動化の仕組みの提案を求めている。

## 提案済みだが未承認の機能
以下はこれまでのアシスタント提案であり、ユーザーが実装仕様として確定したものではない。
- シンボルライブラリ同期: GitHubから初回取得・更新、`sym-lib-table`への登録、更新状況表示、ローカル変更の保護。
- 線番管理: KiCadネットリスト取込、端子間の物理電線の手動定義、既存番号を維持した自動採番、重複・未採番チェック。
- 線番管理: 配線表CSV/Excel、線番チューブ用データ、整合性検証、将来の回路図への線番表示。
- サンプル図面: 電源、PLC構成、入力、出力、端子台・外部配線の5ページ構成。

## 未決定・要確認
- GitHubリポジトリの正式名称、URL、公開/非公開、認証方式、ブランチ、同期対象と保存先。
- GUIツールの正式名称（候補: KiLibSync、KiCad LibHub、KiCad Library Sync）。
- ライブラリの命名規則、ライセンス、シンボル収録範囲。
- 線番管理ツールを実際に開発するか、その正式名称、GUI/CLIの要件。
- 線番の採番規則、重複許容条件、電線色・サイズ等の必須属性。
- 物理電線の分岐、渡り配線、端子台内部接続、複数芯ケーブルの扱い。
- KiCad図面上への線番書き戻しの要否と方式。
- サンプル図面でQ64PN以外に採用するCPU、入出力ユニット、外部電源の正式型式。
- 成果物形式、配布・インストール方法、対応OSの正式な要求。

## 非要求・注意
- 過去に検討したPCBエディタへのボタン追加は、現時点の希望方式ではない。
- 会話中の例示番号（101、102など）や型式（Q03UDECPU、QX40、QY40Pなど）は確定仕様ではない。

## 初版の承認済み要件（2026-10-20）
ユーザーの「実装を進めてください」により、直前に提示した構成を承認。以前の提案・未決定項目のうち以下の範囲は本節を優先する。

- Python標準Tkinterの独立GUI。接続元・接続先の機器番号と端子番号を手入力し、1行を物理電線1本とする。
- 接頭辞・開始番号・最小桁数を指定し、一覧順に未採番のみ採番。既存線番を保持し、使用済み番号をスキップ。
- 線番重複・未採番・端子情報不足を検証。重複・不足があれば採番を止め、未採番も含め問題があればCSV出力を止める。
- JSONで電線と採番設定を保存／再読込し、配線表をCSV出力。
- 初版は独立した線番管理ツール。KiCad連携は次段階。
- 正式名称・配布方式・Excel形式・GitHub同期・分岐等の専用モデルは未決定。
