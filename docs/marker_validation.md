# 線番テキストの非表示識別情報の検証

検証日：2026-10-26 / KiCad CLI：10.0.7（Windows）

## 結果

**専用の名前付きグループに線番テキストを所属させる方式が使用可能。** 合成図面で読込・再保存2回・SVG描画内容の一致を確認した。その後、利用者の指示で本体へ組込み済み（D-026）。

## 本体組込みの確認

追加仕様D-027：JSONにない目印付きテキストは、削除確認でOKなら削除計画を含めて処理を続ける。単体74件と書込GUIテストが成功。削除確認・最終確認でのキャンセル、欠落再作成と削除許可の引継ぎ、削除失敗時の復元を確認した。

単体71件とGUI4本が成功。目印の作成・既存管理テキストへの付与・再実行時の重複防止・管理情報にない目印の検出と書込停止・削除と再作成時のグループ整理を確認した。
実図面の固定スナップショットを入力に、一時コピーで13シート・295ネット・136箇所の線番と目印を作成・更新し、KiCad CLIによる接続不変と再実行時の変更なしを確認。最初の元図面を直接参照したテストでは検証中のファイル変更を検出して不合格とし、以後はPowerShellによる直接コピーで固定したスナップショットを使用した。
別の一時コピー（2シート・102ネット）でも88箇所の作成・採番除外削除が成功した。利用者の元図面・JSONへの書込は実施していない。GUIコピー／貼付け等の未検証事項は下記のとおり。

| 方式 | KiCad読込 | 再保存2回での保持 | SVG描画 | 評価 |
|---|---|---|---|---|
| 通常テキストに独自propertyを追加 | 失敗 | 未実施 | 出力不可 | 不採用候補。通常テキストのpropertyはパーサーが拒否する |
| 専用名のgroupにテキストUUIDを登録 | 成功 | グループ名・グループUUID・メンバーのテキストUUIDを保持 | 目印なしと一致 | 推奨候補 |
| テキストUUIDに専用の接頭部分を使用 | 成功 | UUIDを保持 | 目印なしと一致 | 既存UUIDの維持やコピー時の再採番との相性を別途検討する必要あり |

## 専用グループの例

```scheme
(group "KiWireManager.WireNumber/v1"
  (uuid "63cf656c-caa6-4686-b0a4-07db09d9471a")
  (members "11e86946-5cbb-4d41-a8e3-3aee7f3eac4e"))
```

メンバーUUIDが通常テキストのUUIDを指す。文字列001と書式は変更しない。専用名のグループを調べることで、プロジェクトJSONを参照せずに目印付きテキストを識別できる。
グループ名は通常の図面文字としては描画されないが、KiCadの編集UIでグループとして認識される。

## 検証方法

```powershell
python -B tests/marker_probe.py
```

一時フォルダーに同じ通常テキスト001を持つ合成回路図4種を生成する。利用者の図面・JSONは読み書きしない。
`sch export svg`で読込と描画を確認し、読込成功したケースは`sch upgrade --force`でKiCad自身による再保存を2回行う。
各回で識別情報の残存とSVGのXML全体を比較する。比較から除外するのは生成日時を含むtitle要素のみで、描画要素はすべて保持する。
最終成功時の成果物：`C:\Users\cotec\AppData\Local\Temp\kiwire-marker-results-9y4i1fxf`。results.json、入力図面、保存後図面、SVGを保持した。一時ファイルは将来削除される可能性があるため再実行可能なスクリプトも残す。

## 未検証・今後の判断

- GUIでの通常保存・移動・コピー／貼付け・グループ解除後の保持。CLI再保存の保持は確認済みだがGUI操作全般の保証ではない。
- グループ化に伴う選択・移動操作への影響。
- 実図面の階層・複数配置を含めた管理情報の復旧。
- 目印からのテキスト検出と、ネットへの再対応付けは別処理。専用グループだけではネットを特定できない。
- 過去の目印なしテキストを自動で確実に判別することはできない。初回移行ではJSONの管理UUIDを使い、管理外の候補は利用者確認が必要。
