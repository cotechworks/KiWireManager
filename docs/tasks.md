# 実装タスク管理

更新日：2026-10-26

## 運用ルール

- 未着手・進行中・保留のタスクは「未完了タスク」に記載する。
- 実装・開発側の検証完了と利用者確認の完了を分けて管理する。利用者確認が必要な場合は、実装タスクを完了とする時点で、別IDの確認用タスクを「未完了タスク」へ状態「未確認」で追加する。
- 確認用タスクには対象の実装タスクID・関連決定・具体的な確認項目を記載する。開発側のテスト成功だけで確認済みとせず、利用者の確認報告に基づいて確認日・結果を記録する。一部のみ確認済みの場合は未完了のまま残りの項目を明記する。
- 受け入れ条件を満たしたタスクは状態を「完了」に変更し、行を「完了済みタスク」へ移動する。
- 移動時もタスクID・関連決定・検証結果・利用者確認の記録を保持し、重複掲載しない。
- 完了済みタスクを再開する場合は「未完了タスク」へ戻し、状態と再開理由を記載する。
